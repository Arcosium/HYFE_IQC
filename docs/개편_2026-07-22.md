# GenomicWQB 개편 — 2026-07-22 (야간 작업 보고)

BRAIN 공식 문서 77편과 레퍼런스를 전부 받아와, 2026-07-21 발굴에서 **손으로 하던 것**을

## 1. 가장 큰 발견 — GA 가 최고 필드들을 **보지 못하고 있었다**

`classify_family()` 가 필드명 **접두사로 추측**하고 있었다. 그 결과 7/21 최고 알파를
만든 필드들이 전부 `None` 으로 떨어져 팔레트에서 통째로 빠져 있었다:

| 필드 | 실측 단독 Sharpe | 개편 전 분류 |
|---|---|---|
| `opt6_vimtaxp` (option6) | **2.18** | None |
| `executed_short_trade_share_count` (us_short_sale) | **2.28** | None |
| `shrt36_svol` (shortinterest36) | **1.84** | None |
| `customer_vol_imbalance` (order_flow_imb) | — | None |

**수정**: 필드 → 데이터셋 → 카테고리 **실매핑**으로 분류한다. 데이터셋별로
`/data-fields?dataset.id=…` 를 돌려 매핑을 직접 수집했다(`docs/brain_reference/
field_dataset.json`) — `/data-fields` 가 count 를 10000 으로 캡하고 알파벳순으로 주는
탓에 CSV 만으로는 뒤쪽 데이터셋이 영영 안 보이기 때문이다.

**결과**: `shortinterest` · `imbalance` 계열이 GA 에 **처음 열렸다**. 개체군 16개에서
8개 계열이 고르게 나온다.

## 2. 탐색 조건 시스템 (신규)

Power Pool 주간 테마처럼 "이 조건에 맞는 알파" 요구가 상시로 온다. 조건을 걸면
GA 가 도는 내내 **조건 밖 알파를 애초에 만들지 않는다**.

```bash
python3.12 scripts/constraint.py --set \
  "region=USA & delay=1 & universe=TOP1000 & \
   High Turnover returns ratio test PASS & datasets not in ['pv1']"
python3.12 scripts/constraint.py --set "USA 딜레이1 TOP1000에서 pv1 제외하고 고회전 수익보존"
python3.12 scripts/constraint.py            # 보기
python3.12 scripts/constraint.py --clear    # 해제
```

필터 문법과 한/영 자연어를 모두 받는다. **재시작 불필요**(워커가 라운드마다 재독).
검증: 조건 하 24개체 생성 → 설정 위반 0, 금지 필드 0.

막는 층이 5겹이다 — 합성필드 전개식(`syn_clv` → close/high/low)과 조건식 유전자
(`trade_when`·`regime`·`group_by` 가 pv1 을 하드코딩)까지 잡는다. 최종 안전망은
시뮬 후 WQB 가 준 실제 `datasets` 로 다시 검증하는 `compliant()` 다.

**현재 걸린 조건**: 이번 주 Power Pool 테마 (USA/D1/TOP1000/HT비율/pv1 제외)

## 3. 노브 스윕 — GA 에 없던 연산

7/21 발굴이 통한 진짜 이유는 무작위 변이가 아니라 **엘리트의 노브를 한 축씩 훑은 것**이다.
완전히 같은 식에서 중립화만 바꿔 Sharpe **1.72 → 2.47**, 감쇠만 바꿔 회전율 100% → 48%.
무작위 변이는 여러 축을 동시에 흔들어 인과를 지운다.

포커스 라운드의 앞 2슬롯(`IQC_SWEEP_SLOTS`)을 스윕에 배정한다:
- 슬롯 0 = 중립화 축 (**STATISTICAL 부터** — 실측 최고)
- 슬롯 1 = 감쇠 축 (회전율 제어기가 목표값을 계산)

부모 대비 **딱 한 유전자만** 다르므로 결과 차이를 그 축에 귀속시킬 수 있고,
다음 라운드의 밴딧/정향변이가 그걸 배운다.

## 4. 회전율 ↔ 감쇠 폐루프 제어

실측 곡선(동일 식): decay 0→100.5% · 2→79.6% · 4→62.0% · 6→53.3% · 8→48.5%.

`smooth` 지시가 눈감고 decay 8/12/20 으로 점프하던 것을, 부모 회전율이 측정돼 있으면
**필요한 만큼만** 올리도록 바꿨다(`decay_for_target_turnover`, 목표 60%).
맹목 점프는 Sharpe 를 통째로 버린다(같은 식이 decay 4 에서 1.9, 20 에서 1.2).

## 5. 중립화 사전확률 개정

`FAMILY_NEUTRALIZATION` 전 계열의 **1순위를 STATISTICAL 로** 올렸다.
동일 식 실측: SUBINDUSTRY 1.72 · SECTOR 1.40 · INDUSTRY 1.58 · MARKET 1.19 ·
**STATISTICAL 2.47** (MDD 도 9%대 → 4.35%). HT 하위분류 3종(AFTER_COST·INVESTABLE·
LIQUID)도 함께 얻는다.

⚠ RAM 은 사전확률에 **넣지 않았다** — 가격반전 신호를 통째로 지운다(2.38 → 0.46).
Orthogonal 하위분류를 노릴 때만 의도적으로 쓸 것.

## 6. 문서 RAG (신규)

BRAIN Learn 77편(43만자) + 레퍼런스를 arcembed 로 임베딩해 검색층을 얹었다.

```bash
python3.12 scripts/ask_brain.py "IS ladder thresholds"
python3.12 scripts/ask_brain.py "고회전 알파 제출 조건" -k 3
python3.12 scripts/ask_brain.py --rebuild     # 문서 갱신 후
```

459청크 · 1024차원 · 8.9MB. arcembed 가 죽으면 키워드 검색으로 자동 강등(fail-soft).

왜 만들었나 — 7/21 에 결정적이었던 사실들이 **전부 문서에 있었는데** 우리는 모르고
라이브 A/B 로 역산하고 있었다: IS Ladder 문턱표, CHN 컷, Genius 타이브레이커 7종,
Multi-Simulation 이 순차 실행이라는 사실(우리는 반대로 알고 있었다).

## 7. criteria.py 문서 근거 정정

역산 추정을 공식 문서로 교체했다:
- **CHN 전용 컷** — Sharpe 2.08/3.5, **Returns 하한 8%/12%**(USA 엔 이 체크 자체가 없다),
  Robust Universe 40% 유지. 라이브 프로브로 문서값 확인(`bldVO39p`·`xAd9bMEp`).
- **SuperAlpha 회전율 2~40%** (알파와 다르다)
- **Weight 상한 10%**
- **IS Ladder 3단계** (0.75× / 0.85× / 1.0×) — ⚠ 회전율이 **높을수록 더 높은 배수**를
  넘어야 한다(완화가 아니라 강화). 한때 반대로 이해했던 것을 바로잡았다.
- **자기상관 예외조항** — 0.7 초과라도 상관 알파보다 Sharpe 가 **10% 이상 높으면 통과**.
  제출된 `akEMEvk6` 이 자기상관 0.876 으로 통과한 실제 이유다.

## 8. 폴링 429 버그 수정 (처리량 16% 회복)

`poll()` 이 **응답을 못 읽은 턴도 '진행 없음'으로 세고** 있었다. 8워커가 5초마다 긁으면
폴링 자체가 429 를 맞는데, 그때 `status=None` 이 계속 같은 값으로 찍혀 멀쩡히 돌던 시뮬을
900초에 죽였다(실측: 최근 25건 중 4건). 이제 비정상 응답 턴은 정체 카운터에서 제외하고
Retry-After 가 없으면 자체 백오프한다.
