# GenomicWQB 개편안 — 2026-08-05

8/5 "13시까지 4건 제출" 미션에서 얻은 실측을 근거로 정리한다. 결과는 제출 0건이었고,
그 실패 과정에서 머신의 구조적 결함 여섯 개가 드러났다.

## 1. 진단 — 왜 12일을 헛돌았나

### 1.1 게이트 모델이 현실과 어긋난 채 굳었다 (최우선)

`criteria.submittability()` 가 이렇게 짜여 있었다.

```python
return max(ht_progress(metrics), standard_progress(metrics, delay))
```

"고회전 자격을 얻으면 표준 컷(Sharpe·Fitness)이 WARNING 으로 강등된다"는 가정이다.
7월엔 그 가정이 맞았다. 제출 성공작 21건의 fitness 가 0.26~0.86 으로 **전부 공식 컷(1.0)
미달**인데 통과했다. 그런데 8/3 이후 집행이 바뀌었고, 8/5 실측에서
`MATCHES_CLASSIFICATION=["High Turnover","Investable High Turnover"]` 를 받은 알파가
`LOW_FITNESS(0.65 vs 1.0)` **단독 사유로** 403 을 맞았다(9q7E7J0r 외 8건).

WQB 공식 문서는 10개월째 `Submission Criteria: Fitness >= 1` 을 명시해 왔다. 문서가 바뀐 게
아니라 집행이 바뀐 것이고, 우리는 예외를 표준으로 알고 12일치 알파 6,000건을 쌓았다.

**진짜 문제는 가정이 틀렸다는 게 아니라, 틀렸다는 걸 알아챌 장치가 없었다는 것이다.**
거절 응답에는 매번 정답이 들어 있었는데(`LOW_FITNESS result=FAIL limit=1.0`) 아무도 안 읽었다.

### 1.2 사다리를 목표로 삼지 않는다

GLB 에서 `IS_LADDER_SHARPE` 생존율은 **1.4%(7/499)** 다. 그 7건도 전부 한 가계
(`dsrt × absolute_price_oscillator`)다. fitness ≥ 1.0 인 GLB 알파 243건은 **전원 사다리 사망**,
격차 중앙값 +1.59.

그런데 `reward.py` 에 사다리 항이 없다. `_stability_term` 은 `sharpe_2y` 를 본다.
사다리는 `focus_priority` 에서 **손절 신호로만** 쓰인다. 즉 머신은 사다리를 피하기만 하고
겨냥한 적이 없다. 12일간 최근 구간 성과를 한 번도 최적화 대상으로 두지 않았다.

### 1.3 서브유니버스 컷이 움직이는 표적이다

8/5 실측으로 처음 확인했다. `LOW_SUB_UNIVERSE_SHARPE` 의 컷이 **알파 자신의 샤프에 비례해
올라간다.**

| 알파 샤프 | 서브유니버스 컷 |
|---|---|
| 3.09 | 1.89 |
| 3.38 | 2.07 |
| 3.49 | 2.14 |

샤프를 올릴수록 관문도 같이 도망간다. 머신은 이 관계를 모르고 샤프를 단조 증가 목표로 민다.

### 1.4 가계 붕괴 — 죽은 부모를 계속 연마한다

8/4 실측: focus 라운드가 부모 #10(`LOW_SHARPE 1.11 vs 1.58`)을 여러 시간 반복 연마했고,
그 라운드 산출물 14~16건이 전부 같은 골격(`ts_corr(last_trade_price_60m_post_open,
absolute_price_oscillator_50d)`)의 변주였다.

`focus_priority` 의 손절은 사다리 실패와 PROD 초과만 본다. 이 부모는 둘 다 없어서 안 잘린다.
샤프·핏이 컷에 한참 못 미치는 부모를 손절하는 규칙이 없다.

### 1.5 제출을 너무 아낀다

거절은 쿼터를 **한 건도** 쓰지 않는다. 8/5 에 20건 넘게 쏘고도 `REGULAR_SUBMISSION 0/4` 였다.
그런데 머신의 하루 목표는 4건이고, 제출 문턱을 넘은 알파만 쏜다. 무료로 얻을 수 있는
**오늘 기준 판정**을 안 받아 오고 있다.

### 1.6 라운드 루프가 표적 탐색에 느리다

라운드는 9~20분에 스펙 8개를 소비한다. 8/5 에 직접 API 로 병렬 시뮬(동시 8, 슬롯 대기)을
돌리니 같은 시간에 훨씬 넓은 좌표를 훑었다. 가설이 뚜렷할 때 라운드 큐를 경유하는 건 낭비다.

## 2. 개편 항목

### P0 — 게이트 자가교정 (`criteria` + 신규 `gate_watch`)

거절·체크 응답에서 **오늘 실제로 차단하는 체크 집합**을 추출해 저장한다. 하드코딩된
`is_blocking` 을 실측으로 덮어쓰고, 집합이 바뀌면 대시보드에 경보를 띄운다.

- 원천: `submit_alpha` 403 body 의 `is.checks` (이미 받고 있으나 버린다), `GET /alphas/{id}/check`
- 판정: FAIL 인데 제출이 통과한 체크 = 소프트, 단독 FAIL 로 403 이 난 체크 = 하드
- 산출: `data/gate_profile.json` (날짜별 이력) + 변경 시 로그
- 효과: 8/3 같은 집행 변경을 **당일에** 잡는다. 오늘 우리는 이틀 늦었다

### P0 — 사다리를 보상에 넣는다 (`reward`)

`ladder_sharpe / ladder_sharpe_cutoff` 를 진척도로 정규화해 `_route_term` 과 같은 급으로 올린다.
사다리 없는 알파는 제출 불가이므로, fitness 와 마찬가지로 **우회 불가 관문**이다.

```python
route = min(fitness_progress, ladder_progress, max(ht_progress, standard_progress))
```

미측정은 `None` 으로 두고 게이트를 적용하지 않는다(8/5 에 이 실수로 GA 기울기를 죽였다가
테스트가 잡아냈다).

### P1 — 서브유니버스 컷 모델링 (`criteria`)

컷이 샤프 종속이라는 실측을 반영한다. 최소한 `sub_universe_sharpe_cutoff` 를 알파별 실측값으로
쓰고(이미 metrics 에 있다), 샤프를 올릴 때 컷이 따라 오르는 폭을 진척도 계산에 넣는다.
샤프 3.5 근처에서 서브유니버스가 병목이 되는 구간을 GA 가 인지해야 한다.

### P1 — 부모 손절 확대 (`focus_priority`)

사다리·PROD 외에 **샤프·핏이 컷의 일정 비율 미만인 부모**를 손절 대상에 넣는다.
8/4 의 #10(`S 1.11 vs 1.58`, `fit 0.53 vs 1.0`)이 몇 시간을 먹었다.
기준은 `submittability < 0.6` 정도가 적당해 보이나 실측으로 조정한다.

### P1 — 무료 체크 상시 활용 (신규 `check_sweep`)

`GET /alphas/{id}/check` 는 쿼터를 안 쓴다. 하루 한 번 최근 알파 상위 N건에 대해 오늘 기준
체크를 받아 온다. 용도 둘.

1. 게이트 프로파일 갱신(P0 의 원천)
2. 어제까지 미달이던 알파가 기준 변동으로 통과 가능해졌는지 탐지

### P2 — 표적 캠페인 모드 (신규 `campaign.py`)

병목이 특정되면 라운드를 우회해 직접 병렬 시뮬을 돌린다. 8/5 에 손으로 만든 것을 코드로
남긴다. 필요한 부품은 이미 다 있다.

- 슬롯 429 대기 재시도 (`submit_simulation` 이 `'RATE_LIMITED'` 만 돌려주고 재시도를 안 한다 —
  이건 라이브러리 쪽에서 고치는 게 맞다)
- 결과 수확 → 관문별 진척도 표로 정리
- 통과작 즉시 제출

### P2 — 포트폴리오 다변화 지표

Power Pool 점수는 개수가 아니라 풀에 더한 순증분이다(7/28~8/3 제출 21건 중 11건이
`rsk70_mfm2_gemtrd` 한 데이터셋이었다). 데이터셋·스코프 집중도를 대시보드에 띄우고,
집중도가 높으면 다변화 웨이브 크기를 자동으로 키운다. 창 밖 상시 다변화는 8/4 에 넣었으니
그 위에 지표만 얹으면 된다.

## 4. 내일의 출발점 — 8/5 측정 좌표

최고 후보들이 남긴 위치. 관문 다섯 중 넷을 넘겼고 사다리 하나가 남았다.

| 알파 | S | fitness | 사다리 | 서브유니버스 | 회전율 |
|---|---|---|---|---|---|
| 1Yp59vXJ | 3.45 | 1.07 ✅ | **1.57** / 1.58 | 1.73 / 2.11 | 0.588 ✅ |
| 9qpQYJ0K | 3.09 | 0.91 | 1.55 / 1.58 | 1.96 / 1.89 ✅ | 0.655 ✅ |
| LLGxLVn9 | 3.62 | 1.01 ✅ | 1.12 | 1.58 / 2.22 | 0.780 ❌ |

**신호 구조 실측**

- GLB 에서 fitness 를 내는 엔진은 사실상 하나다.
  `inst18_fundownershipv2_cur_mv / rank(count_institutional_sellers_security)`
  — fit ≥ 1.0 알파 120건 중 **120건**이 이 조합. 단독 fit 1.67, 사다리는 −0.22 로 죽어 있다
- 사다리를 통과하는 가계도 하나다.
  `vector_neut(ts_av_diff(rsk70_mfm2_gemtrd_dsrt,120), ts_mean(absolute_price_oscillator_50d,252))`
  — 사다리 2.42, 회전율 0.578 이라 fitness 0.61
- **결합 방식이 사다리를 좌우한다.** `add(rank(A),rank(B))` 는 사다리를 보존하고(1.12),
  `vector_neut(A,B)` 는 죽인다(0.30)
- 비중 기울기: dsrt 비중을 올리면 사다리 +0.05 당 fitness −0.16. 비중만으로는 둘을 동시에 못 맞춘다

**막다른 길로 확인된 것** — 다시 시도하지 말 것

- 감쇠로 회전율 절감: decay 8 이 이미 최적. 16~48 에서 샤프 2.28 → 0.81, 사다리 2.42 → 0.42
- `hump` 로 회전율 절감: 회전율 0.095 까지 내려가지만 샤프 0.24, 사다리 0.41
- `ts_target_tvr`: 이 계정에서 접근 불가 연산자
- 느린 dsrt(`ts_mean`/`ts_zscore` 250·500): 회전율은 0.11 로 내려가나 사다리 −0.36~0.25
- Barra 단일 팩터 직접 설계(가치·퀄리티·저변동·리버설 18종): 샤프 0.36 이하
- USA 리전: 8월 테마가 GLB 라 `PURE_POWER_POOL_THEME` 로 전부 차단

**남은 길** — 사다리는 최근 구간에서 실제로 작동하는 신호에서만 나온다. 파라미터 조정으로는
못 만든다. 새 데이터축 발굴이 유일한 방향이고, 위 좌표가 그 출발점이다.
