# GenomicWQB 2.0 UI 개편 제안

## 무엇을 바꿀 것인가

현재 화면은 실행 버튼과 실시간 로그, 제출 내역, 진화 차트를 한곳에 모은 운영 대시보드다. 기존 워커를 지켜보기에는 충분하지만 2.0에서 새로 생긴 탐색 모드와 데이터셋 다양성, 실험 상태, Evidence Card를 읽기에는 맞지 않는다. 이제는 사용자가 지금 무엇을 탐색하는지, 왜 후보가 남았는지, 어느 단계에서 탈락했는지, 다음 라운드가 무엇을 배웠는지를 바로 알 수 있어야 한다.

## 첫 화면은 Research Control Room

로그보다 현재 정책과 연구 범위를 먼저 보여준다. 상단 한 줄에는 실행 상태, 라운드, 정책 버전, 탐색 모드, WQB 세션 상태를 놓는다. 그 아래에는 이번 라운드 후보 수, 시뮬레이션 수, 새 데이터셋 수, 제출 가능 후보 수, PROD 상관 거절 수를 둔다.

현재의 숫자 타일은 다음 항목으로 교체한다.

| 항목 | 표시값 | 클릭했을 때 |
|---|---|---|
| 탐색 모드 | hypothesis / exploit / escape | 전환 근거와 최근 변경 이력 |
| 데이터셋 커버리지 | 이번 라운드 N종, 최근 60개 M종 | 데이터셋 지도 |
| 고유 실험률 | canonical 고유 후보 / 생성 후보 | 중복·재사용 내역 |
| 제출 관문 | 준비 / 보류 / PROD 거절 | 제출 퍼널 |
| 세션 | 정상 / 만료 임박 / 인증 필요 | 바이오 인증 동선 |

## 데이터셋 지도

2.0은 한 데이터셋의 성적을 거듭 다듬기보다 서로 다른 데이터셋에서 독립된 신호를 찾는다. 데이터셋 화면도 단순 사용 횟수가 아니라 연구 포트폴리오를 보여줘야 한다.

행에는 데이터셋, 열에는 실험 상태를 둔다. 상태는 생성, 사전 차단, 시뮬 완료, 제출 시도, PROD 통과로 나눈다. 셀에는 후보 수와 최고 Sharpe를 함께 적는다. 최근 60개에서 쓰지 않은 데이터셋은 빈칸으로 숨기지 않고 다음 탐색 후보로 표시한다. risk70처럼 상관 거절이 쌓인 데이터셋은 사용 횟수보다 `PROD 통과율`을 앞에 둔다.

화면 위에는 다음 세 값을 고정한다.

- 이번 라운드 고유 데이터셋 수
- 최근 60개에 없던 데이터셋 수
- 단일 데이터셋 최고 비중과 25% 상한

데이터셋을 누르면 해당 계통의 표현형, 지역 Sharpe, 2년 Sharpe, PROD 상관 분포가 열린다. 여기에서 신규 탐색, 휴면, 금지 상태를 바꿀 수 있게 하되 기본값은 자동 정책으로 둔다.

## 상태 기계로 보는 실험

현재 GA 파이프라인은 생성 방식의 구성을 잘 보여주지만 후보가 어디서 사라졌는지는 찾기 어렵다. AutoZoom의 작업 흐름처럼 다음 여섯 단계를 가로로 배치한다.

`Candidate → Preflight → Simulation → Gate → Submit → Observe`

각 단계에는 현재 건수, 실패 건수, 대기 시간을 표시한다. 단계를 누르면 그 상태의 실험만 목록에 남는다. 실패 후보는 오류 문장 전체보다 `중복`, `데이터셋 집중`, `지역 Sharpe`, `2Y`, `PROD 상관`처럼 판단에 필요한 이유를 먼저 보여준다. WQB 원문 응답은 상세 화면에서 확인한다.

## Alpha Evidence Card

현재 알파 상세 창은 지표와 제출 대기 기능이 중심이다. 2.0에서는 Evidence Card가 상세 화면의 첫 장이 된다. 순서는 가설, 부모, 바뀐 유전자, 사용 데이터셋, 기대 효과, 실제 결과, 제출 응답, 후속 관측, 결론이다.

결론은 `유망`, `상관벽`, `지역 불균형`, `장기 성능 부족`, `컴파일 오류`, `중복` 가운데 하나로 표시한다. 근거가 없으면 결론도 만들지 않는다. 숫자를 누르면 해당 WQB snapshot과 관측 시각이 열린다. 같은 canonical key를 다시 만났다면 새 카드를 만들지 않고 이전 카드와 재사용 횟수를 보여준다.

## 탭 구조

| 탭 | 역할 |
|---|---|
| 연구실 | 현재 정책, 라운드, 데이터셋 커버리지, 핵심 경보 |
| 실험 | 상태 기계와 후보 목록 |
| 데이터셋 | 사용 폭, PROD 통과율, 휴면·금지 상태 |
| 증거 | Evidence Card와 WQB snapshot |
| 제출 | 제출 퍼널, 일일 예산, 거절 사유 |
| 로그 | 원문 운영 로그. 기본 탭에서는 제외 |

모바일은 연구실, 제출, 인증 세 화면부터 제공한다. 데스크톱 차트를 전부 줄여 넣지 않고 데이터셋 커버리지와 인증 경보만 남긴다.

## 시각 원칙

지금의 종이·잉크 원장 테마는 유지한다. 새 카드와 상태가 늘더라도 둥근 상자와 색상 면을 추가하지 않는다. 상태는 괘선, 작은 사각 마커, 숫자, 짧은 문구로 구분한다. 데이터셋마다 새 색을 만들지 않고 카테고리별 5색만 쓴다. 개별 데이터셋은 글자와 정렬로 식별한다. 빨강은 오류 전반이 아니라 사용자가 개입해야 하는 상태에만 쓴다.

## 필요한 API

| API | 용도 |
|---|---|
| `/api/v2/overview` | 정책 버전, 탐색 모드, 커버리지, 제출 퍼널 |
| `/api/v2/experiments` | 상태별 실험 목록과 canonical identity |
| `/api/v2/datasets` | 라운드·최근 60개·24시간 데이터셋 통계 |
| `/api/v2/evidence/:id` | Evidence Card와 snapshot 연결 |
| `/api/v2/policies` | 정책 변경 이력과 적용 시각 |

## 적용 순서

먼저 기존 화면을 지우지 않고 연구실 탭과 데이터셋 지도를 추가한다. 다음 배포에서 알파 상세를 Evidence Card로 바꾸고, 마지막에 운영 로그를 보조 탭으로 내린다. 성공 기준은 체류 시간이 아니다. 사용자가 30초 안에 현재 탐색 모드, 가장 많이 쓴 데이터셋, 가장 큰 제출 병목, 다음 라운드가 바꿀 축을 찾을 수 있는지를 본다.
