# 유전 알고리즘으로 알파 리서치하기

## 리포트 개요

### 1. 글의 목적

이 리포트는 GenomicWQB의 개발·운영 사례를 중심으로 유전 알고리즘이 알파 리서치에 어떻게 적용되는지 설명한다. 핵심은 유전 알고리즘을 단순한 수식 생성기로 보는 것이 아니라, 제약이 많고 평가 비용이 비싼 탐색 문제를 관리하는 리서치 방법론으로 해석하는 것이다. 알파를 유전체로 표현하고, 시뮬레이션 결과에 따라 선택·교차·변이를 반복하며, 모든 계보와 실패 원인을 기록하는 과정에 초점을 둔다.

보고서의 중심 주장은 다음과 같다. 유전 알고리즘의 가치는 단 하나의 최고 수식을 찾는 데 있지 않다. 넓은 탐색 공간을 재현 가능한 실험 단위로 쪼개고, 성과가 좋은 구조를 다음 세대로 넘기며, 실패에서도 다음 실험 방향을 얻는 데 있다. GenomicWQB는 여기에 LLM의 가설 생성, 다목적 선택, 밴딧 기반 슬롯 배분, WorldQuant BRAIN의 실측 평가를 결합한 혼합형 연구 시스템이다.

### 2. 연구 질문

| 구분 | 질문 |
|---|---|
| RQ1 | 무작위 탐색보다 엘리트 선택·교차·변이를 적용한 탐색이 시뮬레이션당 유효 알파 수를 늘리는가? |
| RQ2 | 여러 유전자를 한꺼번에 바꾸는 변이보다 한 축 스윕과 실패 원인별 정향변이가 개선 효과를 더 분명하게 만드는가? |
| RQ3 | Sharpe 하나만 최대화하는 방식보다 Fitness, turnover, self-correlation, 제출 가능성을 함께 보는 다목적 선택이 더 다양한 엘리트 풀을 유지하는가? |
| RQ4 | 주간 테마와 계정별 제약을 생성 단계에 반영하면 조건 밖 후보에 쓰는 시뮬레이션을 줄일 수 있는가? |

### 3. 전체 구성

#### I. 서론: 왜 알파 리서치에 탐색 알고리즘이 필요한가

알파 수식은 데이터필드, 시계열 변환, 결합 방식, 룩백, 중립화, 감쇠, 이상치 처리 등 여러 선택의 조합이다. 가능한 조합은 빠르게 늘지만 각 후보의 품질은 WorldQuant BRAIN 시뮬레이션을 돌린 뒤에야 알 수 있다. 평가가 느리고 동시 실행 슬롯도 제한되므로 전수 탐색은 현실적이지 않다. 이 장에서는 알파 리서치를 ‘거대한 조합 공간에서 제한된 평가 예산을 배분하는 문제’로 정의한다.

#### II. 이론적 배경: 유전 알고리즘과 알파 탐색

유전 알고리즘의 기본 요소인 개체, 유전체, 적합도, 선택, 교차, 변이를 알파 리서치의 언어로 바꿔 설명한다. 유전 프로그래밍과의 차이도 짚는다. GenomicWQB는 임의의 구문 트리를 무제한으로 진화시키지 않고, 문법과 연구 관행이 반영된 고정 유전자 공간에서 수식을 렌더링한다. 이 선택은 표현 자유도를 일부 포기하는 대신 문법 오류와 과도한 복잡도를 줄인다.

#### III. GenomicWQB의 유전체 설계

알파 한 개는 데이터 계열과 세 개의 필드, 변환 연산자, 결합 방식, 부호, 룩백, 유니버스, 중립화, 감쇠, truncation, 결측치 처리, `trade_when`, 그룹 연산, winsorization, 가중 방식, regime, `hump` 등의 유전자로 구성된다. 렌더러는 이 유전체를 FASTEXPR 수식과 시뮬레이션 설정으로 바꾼다. 룩백을 2·3·5·10·20·60·120·252일로 제한한 이유와 기본 유전자에서 기존 코드가 변하지 않도록 한 하위 호환 설계도 설명한다.

이 장의 핵심 그림은 ‘유전체 → 표현식과 설정 → WQB 시뮬레이션 → 지표’ 흐름도다. 유전자와 실제 알파 표현식의 대응 예시도 한 건 넣는다.

#### IV. 진화 루프의 구조

한 라운드는 최근 유전체 가운데 엘리트를 고르고, 교차·변이·무작위 탐색·전략 스펙으로 다음 개체군을 구성하는 단계에서 시작한다. 이후 문법, 중복, 데이터 가용성, 테마 조건을 사전 검사하고 통과한 후보만 시뮬레이션한다. 결과는 DB에 유전체와 부모 ID, 세대, 바뀐 유전자와 함께 저장된다.

선택 과정에서는 연속 적합도와 NSGA-II를 함께 다룬다. 연속 적합도는 완전 통과 전의 ‘근접 실패’에도 선택압을 준다. NSGA-II는 Sharpe, Fitness, 제출 경로 점수, self-correlation, 최근 2년 Sharpe를 목적축으로 삼아 파레토 면과 혼잡 거리를 계산한다. 단일 가중합이 한 유형의 알파로 수렴하는 문제를 줄이기 위한 장치다.

#### V. 단순 변이에서 학습형 탐색으로

GenomicWQB의 변이는 완전한 무작위가 아니다. 실패 항목과 부모 지표를 보고 바꿀 유전자 범주를 정하며, 성공률이 쌓이면 Thompson sampling으로 변이 지시를 선택한다. 별도의 스윕 슬롯은 중립화나 감쇠처럼 결과에 큰 영향을 주는 축을 하나씩 바꾼다. 부모와 자식의 차이가 한 축으로 제한되므로 성과 변화의 원인을 해석하기 쉽다.

밴딧은 유니버스, 중립화, 감쇠 구간, 데이터 패밀리, 결합 방식에 시뮬레이션 슬롯을 배분한다. 완전 통과만 보상하면 학습 신호가 지나치게 희소해지므로 제출 가능 보상과 연속 선택 점수를 섞는다. 이 구조에서 LLM은 새로운 가설과 전략 스펙을 만들고, 유전 알고리즘은 반복 탐색과 계보 관리를 맡는다.

#### VI. 실증 분석 설계

비교 대상은 무작위 탐색, LLM 전략 스펙 단독, 기본 GA, 정향변이·밴딧·다목적 선택을 모두 적용한 전체 시스템으로 나눈다. 같은 리전, delay, universe, 주간 테마 안에서 비교해야 하며 플랫폼 규칙이 바뀐 기간은 별도 구간으로 나눈다.

| 평가 영역 | 지표 |
|---|---|
| 생산성 | 100회 시뮬레이션당 유효 후보 수, 제출 시도 수, 제출 성공 수 |
| 탐색 효율 | 최초 유효 알파까지 필요한 시뮬레이션 수와 시간, 근접 실패의 다음 세대 전환율 |
| 성과 | Sharpe, Fitness, returns, turnover, IS Ladder Sharpe, sub-universe Sharpe |
| 다양성 | 데이터 패밀리 분포, 필드 조합 수, 표현식 유사도, self/prod-correlation, 엘리트 풀 엔트로피 |
| 진화성 | 최고 세대 깊이, 부모 대비 자식 개선폭, 교차·변이·무작위 기원별 수율 |
| 운영 안정성 | API 오류율, 타임아웃, 취소율, 캐시 적중률 |

통과율 차이는 비율과 신뢰구간으로 제시하고, 연속 지표는 중앙값과 분위수 또는 부트스트랩 신뢰구간을 사용한다. 리전·테마·데이터 패밀리가 섞인 자료는 층화해서 비교한다. 운영 오류는 알파 품질 실패와 분리한다.

#### VII. 사례 분석

사례는 세 종류가 적합하다. 첫째, 한 유전자만 바꾼 중립화·감쇠 스윕에서 Sharpe나 turnover가 달라진 경우다. 둘째, 높은 Sharpe만 좇던 엘리트 풀이 한 가계에 고착된 뒤 NSGA-II와 최근성 윈도우로 다시 순환한 사례다. 셋째, Power Pool 테마 변경을 늦게 반영해 `PURE_POWER_POOL_THEME` 거절이 발생했고, 자동 동기화와 제약 병합으로 수정한 사례다. 성공 사례뿐 아니라 탐색이 잘못된 목적함수에 적응한 장면을 함께 보여주면 유전 알고리즘의 장점과 위험이 모두 드러난다.

#### VIII. 한계와 결론

WQB는 외부의 블랙박스 평가기이므로 로컬에서 동일한 결과를 재현하기 어렵다. 플랫폼 규칙과 주간 테마가 바뀌어 적합도 함수가 고정되어 있지 않으며, 시스템 개선이 계속된 탓에 시기별 성과를 단순 비교하면 교란이 생긴다. IS 성과가 실거래 수익을 보장하지 않고, 반복 탐색 자체가 IS 과적합을 키울 수도 있다. 제출된 알파만 보면 생존자 편향도 생긴다.

결론에서는 유전 알고리즘을 ‘자동으로 돈 버는 수식을 찾는 장치’가 아니라 ‘알파 실험을 구조화하는 장치’로 평가한다. GenomicWQB의 가장 중요한 산출물은 최고 성과 알파 한 건뿐 아니라 어떤 유전자가 어떤 환경에서 작동했고, 무엇이 실패했는지를 남긴 실험 원장이다.

### 4. 권장 도표와 표

1. GenomicWQB 한 라운드의 데이터 흐름도
2. 유전체와 FASTEXPR 표현식의 대응표
3. 엘리트 선택·교차·변이·스윕의 계보도
4. 기준선과 전체 시스템의 시뮬레이션당 수율 비교
5. 세대별 최고점과 다양성 변화 그래프
6. 부모·자식 한 축 비교 사례표
7. 실패 원인별 빈도와 다음 세대 개선율

### 5. 자료와 재현 계획

분석 자료는 `alphas`, `rounds`, `submit_attempts`, `bandit_arms`, `strategy_specs` 테이블에서 추출한다. 알파별 코드, 유전체, 세대, 부모 ID, 기원, 변경 유전자, 시뮬레이션 설정과 지표를 묶어 분석용 테이블을 만든다. 보고서에 쓰는 수치에는 집계 기준일과 필터 조건을 함께 적고, 계정 정보와 원본 자격증명은 제외한다. 코드 근거는 `genome_models.py`, `selection.py`, `reward.py`, `worker.py`, `db.py`를 기준으로 삼는다.

### 6. 예상 분량

본문은 15~20쪽이 적당하다. 서론과 이론적 배경에 3쪽, 시스템 설계에 5쪽, 실증 분석과 사례에 7~9쪽, 한계와 결론에 2~3쪽을 배분한다. 부록에는 유전자 목록, 목적함수 정의, 데이터 추출 기준, 추가 실험표를 싣는다.
